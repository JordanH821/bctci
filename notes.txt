Sets and Maps:
- Sets are a unique group of elements
- Maps are a unique group of keys that point to some value
- Keys for sets and maps must be immutable: *****CANNOT USE LISTS OR SETS*****
- Operations are all O(1) given that the hashing is O(1)
	- Hash operations for strings is O(c) where c is the number of characters
- Linear Scan Tradeoff: using a set or map to get constant-time lookups rather than repeated linear scans over an array
- Reusable Ideas:
	- Frequency Maps: using a map of elements to counts
		- Useful in duplicate detection, counting, most frequency element problems
	- Leverage the input range: when the input range is small you can use it to create more efficient solutions, see pg. 349
	- Impose a canonical order: defining an order of elements when using a list (as a tuple) as the key
- Common bugs:
	- Iteration order is not deterministic (in Python3.7+ it is the insertion order)
	- Cannot update a set or map while updating through it
	- Set and map keys cannot be modified
		- Must use immutable data types
	- Not all types are hashable
		- To make a user-defined class hashable you will need to add __hash__() and __eq__() as instance methods
	- Trying to use sets or maps for nearest-element searches

Sorting
- Builtin sorting
	- methods:
		- <Object>.sort() sorts "in place"
		- <Object>.sorted() returns a new sorted list
	- Comparators are deprecated in Python3, use a key function
	- Reverse flag flips the sorting
		- Default is increasing order:
			>>> l = [1,2,3]
			>>> l.sort()
			>>> l
			[1, 2, 3]
			>>> l.sort(reverse=True)
			>>> l
			[3, 2, 1]
			>>>
	- Example:
		>>> A = [(1,'Z'),(1, 'A'), (2, 'B')]
		>>> A.sort()
		>>> A
		[(1, 'A'), (1, 'Z'), (2, 'B')] # NOTE: tuples ties are broken by next value
		>>> A.sort(key= lambda t: (t[1], t[0]))
		>>> A
		[(1, 'A'), (2, 'B'), (1, 'Z')] # NOTE: multiple value sort
		>>> A = [(1,'Z'),(1, 'A'), (2, 'B'), (3, 'A')]
		>>> A.sort(key= lambda t: (t[1], t[0]))
		>>> A
		[(1, 'A'), (3, 'A'), (2, 'B'), (1, 'Z')] # NOTE: multiple value sort more obvious
- Types of sorting
	- Comparison sorts: generic algorithms that can sort any data type
		- Ex: quicksort, mergesort, heapsort
		- Work by directly comparing elements with either builtin or custom comparators
		- Runtime is O(n log n)
			- Actually O(T * n log n), where T is the time it takes to compare elements
				- T is O(l) for strings of length l, but constant for numbers
	- Specialized sorts: algorithms that leverage the input range
		- Ex: counting sort, bucket sort, radix sort
		- Think of dutch flag problem
		- Counting sort: good for arrays that have a smaller input range, basically count all instances of each input and rewrite them in order in the output array
- Reusable Ideas
	- Sort to track largest and smallest elements
- Stable Sorting: Elements that are equal maintain their original ordering
- Algorithms to know:
	- mergesort
	- quicksort
		- quickselect
	- bucket sort

Recursion
- Call Stack: the stack of return addresses that accumulate as a program runs and nested function calls are executed
	- Instruction Pointer: a pointer to the currently executing instruction, when returning from a function this is set to the last return address pushed onto the call stack
	- Stack Overflow: an error that occurs when the memory allocated to the call stack is entirely filled up with return addresses. This is a common error with recursion.
- Call Tree: a tree representing every recusive call over the course of an algorithm execution
- Common Mistakes (see details on pg. 296):
	- 1. Forgotten or incorrect base cases
	- 2. Not making progress
	- 3. Making unnecessary copies
	- 4. Merging recursive calls incorrectly (see reusable idea below)
	- 5. Missing return
- Reusable Idea: Pass indices, not copies
	- Pass indices directly rather than slices or copies as these add to the overhead in both runtime and space complexities
- Design Choices:
	- Helper functions: useful when a different function signature than the given function signature is required
	- Returning values directly or updating a variable: if the variable takes constant space return it directly, but variables that take more than constant space should be updated by reference or made visible (defined outside helper function)
	- Eager vs lazy parameter validation: no clear preference, but lazy only has to be done once in the case of multiple recusive calls (see pg. 400)
		- Eager: valid parameters before passing them recursively
		- Lazy: valid parameters after the recursive call as the base case
- Big O Analysis
	- Memorize common recusive algorithm runtimes: mergesort, quicksort
	- BAD Method:
		- B: Branching Factor: the number of maximum branching facor of any node (how many children the nodes have)
		- A: The upper bound on the amount of Additional work at any particular node
		- D: Depth: the number of levels in the call tree
		- We can bound the total amount of work done by the algorithm by O(b^d * A)
		- Gives a valid upper bound BUT may not be tight
			- Reasons:
				- Not all leaves are at maximum depth
				- Not all non-leaf nodes have the maximum branching factor
				- Not all nodes do the same amount of additional work
	- Space Analysis: the call stack counts as extra space in a recursive function
		- The space complexity will be the max of O(max call depth) and O(additional space)
- Recurrence Relations: a function defined in terms of itself with smaller inputs
	- Ex: factorials, fibonnaci
	- A method for figuring out recursive algorithms is to first define the recurrence relation
- Reusabled Idea: Applying modulo at each step
	- When questions specify to use modulo, you can apply this at each step rather than just at the very end for all math (add, sub, mult) besides division
- Memoization(AKA caching): storing information to avoid recomputing the same value twice
- Dive and Counquer
	- recursive algorithm type where
		- we divide the input into disjoint parts
		- we solve each part recursively
		- We combine the solution to each part into the final solution
	- not very common besides mergesort and quicksort

Linked Lists
- A linked list is a data structure containing an ordered sequence of nodes
	- Two types:
		- Singly Linked Lists: a node only points to the next node
		- Doubly Linked Lists: a node points to previous and next nodes
- Efficiency
	- More efficient to modify in some cases than standard dynamic arrays
		- O(1) vs O(n)
			- push_front()
			- pop_Front()
	- Less efficent than standard dynamic arrays
		- index access: O(index) vs O(1)
		- pop_back(): O(n) for SLL and O(1) for DLL and dynamic arrays
- Reusabe techniques
	- Dummy Nodes: using a dummy node at the head to simplify edge cases and null checks
	- Linked List Reversal Breakdown: using the *breakdown the problem* booster
		1. Find the bounds of the section that needs to be reversed
		2. Break that section out of the list without losing the before and after parts of the list
		3. Reverse the section (see 34.6)
		4. Reattach the section
- Slow and Fast pointers
	- Cycle detection (Floyd's cycle detection algorithm)
		- A cycle in a LL is when a node points to another node that has been seen before
		- Advance the fast pointer more times than the slow pointer on each Iteration
	- Other uses: find the center of a LL in one pass and similar problems
- Triggers:
	- We need O(1) access to beginning and end of a data structure while maintaining insertion order

Trees
- Terminology:
	- Trees consist of nodes, which have children that are other nodes branching out from it
	- The root node is the one at the very top (growing down) and the only one without a parentheses
	- A leaf is a node with no children
	- The branching factor of a node is its number of children
	- The depth, height, or level of a node is the number of ancestors it has; the root node has a depth of 0
	- The depth or height of a tree is the maximum depth among all nodes plus one, or zero if there are no nodes
- Depth-Frst Search (DFS): a traversal algorithm for trees where we go deep into the left subtree visiting everynode, then doing the same for the right subtree
	- Types of DFS traversals:
		- Preorder traversal: the root precedes the subtrees
		- Inorder traversal: the root is in between the subtree
		- Postorder traversal: the root in after the subtrees
- Reusable Ideas:
	- Finding the node in the path with the minimum depth (see 34.3)
- Breadth-First Search(BFS): a traversal algorithm for trees that visits nodes level by level
	- Recipe:
		def node_depth_queue_recipe(root):
			Q = queue()
			Q.add(root)
			while not Q.empty():
				node, depth = q.pop()
				if not node:
					continue
				# Do something with node
				q.add((node.left, depth+1))
				q.add((node.right, depth+1))
- Big O Analysis(Runtime): tree algorithms are analyzed in terms n, the number of nodes, and h, the height of the tree
	- Things to consider
		1. Does it follow one path from top to bottom? In this case runtime is based on height, assuming a constant time amount of work per node, runtime would be O(h)
		2. Does it visit each node once? IN this case, the runtime is based on the number of nodes. If we spend O(1) time on each node, the runtime will be O(n)
		3. Something else? Generally speaking, we can analyze any tree algorithms as the product of two things: the number of node visited and the time spent at each node (not counting recursive work)
	- Most problems can solved by visiting each node once and doing a constant amount of work per node. If your algorithms visits nodes more than once or twice consider it may not be optimal.
- Big O Analysis (Space): space used by recursive tree algorithms comes from the height of size of the call stack
	- O(n) for unbalanced trees
	- O(h) for balanced trees
- Balanced Trees: a binary tree is balanced if for every node the left and right subtrees contain roughly the same amount of nodes (O(log n) height)
	- "Roughly" depends on the type of balanced tree
	- Types of balanced trees
		- Heaps are based on complete binary trees
		- Tree-based sets and maps use self-balanced BSTs
		- The union-find data structure is based on a set of n-ary trees with amortized height even less than O(log n)
- Perfect Binary Tree: is a tree where every level has the maximum number of nodes
	1. all the leaves are at the same depth
	2. all the non-leaf nodes (AKA internal nodes) have two children
- Complete Binary Trees: a tree where all levels except the last one have the maximum numbers of nodes
	- The last level may not be full, but all the nodes are aligned to the left
- Binary Search Trees (BSTs):
	- a binary tree is a BST if for every node:
		1. all the values on its left subtree are less than or equal to the node's value
		2. all the values on its right subtree are greater than or equal to the node's value
	- inorder traversals of a BST goes the the elements in order
	- name comes the relation of trying to find a value in a BST to using binary search
	- we can find any value in a *balanced* BST in O(log n) time
	- Self-Balancing BSTs
		- A self-balancing BST is a BST-based data structure that supports the following operations:
			1. You can insert and remove elements in O(logn) time
			2. You can search for a given value or its nearest value in O(logn) time
		- Examples: Red-black tress, AVL trees
			- The heights of these trees are at most O(logn)
- TreeSets and TreeMaps
	- Sets and maps based on trees
	- Should be used when we need nearest-value search on dynamic data

Graphs
- A data structure made of nodes (AKA vertices) and edges
- Undirected Graph Terminology
	- Adjacent / neighbor nodes are nodes that share an edge between them
	- Nodes can be called endpoints of the edge they share
	- There is a path between two nodes if it is possible to go from one to the other by moving along edges
	- A cycle is a sequence of edges that start and end at the same node
	- V is used for the number of veritces (nodes) and E for the number of edges
	- The degree of a node is the number of neighbors it has. This can range from 0 to V-1
	- A complete graph has the maximum number of edges
	- Parallel edges are an edge from a node to itself and are usually not allowed
	- A graph is connected if there is a path from every node to every other node
	- A connected component is a maximal subset of nodes where every node can reach every other node
- Directed Graph Terminology
	- Edges have a direction that is shown with an arrow. The start of the edge is the source node and the arrow side node is the destination node. (a. b) and (b, a) would be different edges
	- Nodes have incoming and outgoing edges
	- Neighbors are the nodes that can be reach from a source node via outgoing edges
	- The number of incoming edges is called the indegree and the number of outgoing is called the outdegree
	- Paths and cycles must respect the edge directions
- Weighted graphs have a value associated with each edge. while unweighted graphs do not
- Adjacency List Representation: a representation of a graph that is a V lists of neighbors in an array
	- This representation assumes vertices can be identified by indexes from 0 - V-1
		- If this assumption is incorrect we can use a map from node identifier to neighbors. This introduces some overhead for hashing
- Edge List Representation: a graph representation that includes a number of vertices and a list of edges. This representation is not effecient for many problems
- Resuable Idea: Edge List to Adject List Recipe
	def build_adjacency_list(V, edge_list):
		graph = [[] for _ in range(V)]
		for node1, node2 in edge_list:
			graph[node1].append(node2)
			if undirected:
				graph[node2].append(node1)
		return graph
- Adjacency Matrix Representation: a graph representation using a VxV boolean matrix where an edge exists between nodes i and j if matrix[i][j] is True
	- Takes O(V^2) space
	- Better on space for dense graphs because it is less space to store n booleans than n-1 integers; worse for sparse graphs
Big O Analysis (Adjacency List): graphs are analyzed in terms of vertices, V, and edges, E
	- Space Usage: O(V+E)
	- Count nodes, node degree: O(1)
	- Count edges: O(V)
	- Iteration through neighbors of a node: O(degree(node))
	- Find if two nodes are adjacent: O(degree(node1)) or O(1) if a set is just for the internal lists
	- Initialize from edge list and node count, validate adjacency list(no self-loops, no parallel edges, no missing directions): O(V+E)
- Depth-First Search (DFS): a graph traversal algorithm
	- similar to a tree DFS, but we need to account for cycles using a visited node set
	- Good at solving connectivity questions
	- Graph DFS Recipe:
	def graph_DFS(graph, start):
		visited = {start}
		def visit(node):
			# do something with node
			for nbr in graph[node]:
				if nbr not in visited:
					visited.add(nbr)
					visit(nbr)
		visit(start)
	- Connected-Component Loop Recipe
		def connected_component_loop(graph):
			visited = set() # shared across all CC
			for node in graph:
				if not visited yet:
					# Found new connected component
					# Visit all nodes in CC
					visited.add(node)
					visit(node)
	- Runtime: O(V+E)
	- Space: O(V+E), O(V) for visited, O(V+E) for the adjacency list
- Reusable Idea: Path Reconstruction
	- In DFS when we mark a node as visited, we can also track a predecessor in the DFS. The mapping of each node to its predecessor defines a DFS visit tree rooted at the starting node
		- See 36.2 for an Example
	- In BFS this finds the shortest path
- Reusabe Idea: Computing Averages
	- When computing averages it is often easier to focus on computing the numerator and denominator separately and then dividing at the very end
- Breadth-First Search (BFS): a graph traversal algorithm
	- Used to solve both connectivity and distance problems
	- Computes the distance from the starting node to every other node
	- Again, like DFS on graphs, we need to avoid cycles with a visited set
		- We also need to prevent adding duplicates to the pending queue to avoid O(V^2) space

				for nbr in graph[node]:
					if nbr not in distances:
						distance[nbr] = distance[node]+1
