Sets and Maps:
- Sets are a unique group of elements
- Maps are a unique group of keys that point to some value
- Keys for sets and maps must be immutable: *****CANNOT USE LISTS OR SETS*****
- Operations are all O(1) given that the hashing is O(1)
	- Hash operations for strings is O(c) where c is the number of characters
- Linear Scan Tradeoff: using a set or map to get constant-time lookups rather than repeated linear scans over an array
- Reusable Ideas:
	- Frequency Maps: using a map of elements to counts
		- Useful in duplicate detection, counting, most frequency element problems
	- Leverage the input range: when the input range is small you can use it to create more efficient solutions, see pg. 349
	- Impose a canonical order: defining an order of elements when using a list (as a tuple) as the key
- Common bugs:
	- Iteration order is not deterministic (in Python3.7+ it is the insertion order)
	- Cannot update a set or map while updating through it
	- Set and map keys cannot be modified
		- Must use immutable data types
	- Not all types are hashable
		- To make a user-defined class hashable you will need to add __hash__() and __eq__() as instance methods
	- Trying to use sets or maps for nearest-element searches

Sorting
- Builtin sorting
	- methods:
		- <Object>.sort() sorts "in place"
		- <Object>.sorted() returns a new sorted list
	- Comparators are deprecated in Python3, use a key function
	- Reverse flag flips the sorting
		- Default is increasing order:
			>>> l = [1,2,3]
			>>> l.sort()
			>>> l
			[1, 2, 3]
			>>> l.sort(reverse=True)
			>>> l
			[3, 2, 1]
			>>>
	- Example:
		>>> A = [(1,'Z'),(1, 'A'), (2, 'B')]
		>>> A.sort()
		>>> A
		[(1, 'A'), (1, 'Z'), (2, 'B')] # NOTE: tuples ties are broken by next value
		>>> A.sort(key= lambda t: (t[1], t[0]))
		>>> A
		[(1, 'A'), (2, 'B'), (1, 'Z')] # NOTE: multiple value sort
		>>> A = [(1,'Z'),(1, 'A'), (2, 'B'), (3, 'A')]
		>>> A.sort(key= lambda t: (t[1], t[0]))
		>>> A
		[(1, 'A'), (3, 'A'), (2, 'B'), (1, 'Z')] # NOTE: multiple value sort more obvious
- Types of sorting
	- Comparison sorts: generic algorithms that can sort any data type
		- Ex: quicksort, mergesort, heapsort
		- Work by directly comparing elements with either builtin or custom comparators
		- Runtime is O(n log n)
			- Actually O(T * n log n), where T is the time it takes to compare elements
				- T is O(l) for strings of length l, but constant for numbers
	- Specialized sorts: algorithms that leverage the input range
		- Ex: counting sort, bucket sort, radix sort
		- Think of dutch flag problem
		- Counting sort: good for arrays that have a smaller input range, basically count all instances of each input and rewrite them in order in the output array
- Reusable Ideas
	- Sort to track largest and smallest elements
- Stable Sorting: Elements that are equal maintain their original ordering

Stacks and Queues
- Stacks are LIFO - last-in-first-out
	- Use lists in Python since there is no stack class
- Queues are FIFO - first-in-first-out
	- Use collections.deque (double-ended queue) in Python
		- popleft for front, pop for back
		- appendleft for front, append for back
- push, pop, peek, size are all constant time operations
	- underlying dynamic array or linked list
- Reuseable ideas:
	- Piggybacking extra info: store extra fields with main information to help processing
		- Example using counts in 32.2 compress array by k
	- Reframe balanced parenthesis as plot heights: goes up with open, down with close and creates a 'valid mountain range outline' (height >= 0, ends at height == 0)
